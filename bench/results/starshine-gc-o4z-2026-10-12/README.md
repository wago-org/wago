# Starshine GC `-O4z` on Wago PR 948, 2026-10-12

## Result

The reported Wago run took about 176 seconds. On this machine, the pinned PR baseline took **164.554 seconds** at the median of three runs. The first PR changes reduced that to **92.825 seconds**. Checked native constructors for typed collector references and shorter collector reads brought it to **63.040 seconds**. Native reads from open structs brought the latest median to **48.616 seconds**: 70.5% less wall time than the baseline and 22.9% less than the typed-constructor result. All versions produced identical, valid 5,478,001-byte wasm output. [All twelve samples](samples.csv) are included.

Compile and instantiate time was about 1.15 seconds in the latest median. The invoked optimizer accounts for almost all wall time. Phase medians are calculated separately, so they do not add to the whole-command median. Starshine's trace timer has millisecond resolution. It reports `strip-debug` as 0 ms and the main pipeline as less than one second; this input skips many artifact-level optimization passes. The validation and size-selection timers measure Starshine guest code running in Wago, not Wago's compile validator. They remain the costly work here.

The baseline CPU profile sampled 182.96 seconds in a 192.44-second profiled run. The native-to-Go host loop had 140.98 seconds of cumulative samples (77.1%); GC struct helper dispatch had 81.18 seconds (44.4%), and typed struct reads had 30.71 seconds (16.8%). Profile phase labels put 40.9% of samples in size portfolio, 26.6% in candidate selection, and 16.5% in final validation. These are overlapping call stacks, so their percentages must not be added. Repeated reference reads crossed Wago's internal GC helper boundary during validation and size exploration.

The bulk CLI protocol is separate from those internal transitions. Without tracing, Starshine made 19 request/response pairs: one argument query, 15 environment queries, one file-existence query, one bulk read, and one bulk write. The read and write therefore used four host-function calls in total. The no-trace run took 93.244 seconds and produced the same output. Phase tracing added 106 stderr operations and used 124 request/response pairs. Guest host I/O call count does not explain the 164-second baseline.

## Changes and remaining cost

[The amd64 getter](../../../src/core/compiler/backend/railshot/amd64/gc_direct.go) reads a final struct's four-byte collector reference through the checked native object resolver. It publishes the child as an exact operand root. Open struct getters now use a separate native resolver that checks the actual canonical subtype interval before reading a scalar, packed, or collector-reference field. The loaded child remains an exact root across a later allocation. Function and external references keep their checked helper paths. [The resolver pin](../../../src/core/compiler/backend/railshot/amd64/control.go) survives ordinary stack canonicalization, so a later register allocation cannot overwrite a valid raw-address certificate.

[The root plan](../../../src/core/compiler/backend/railshot/shared/gc_frame_roots.go) keeps each collector-reference local's source type after frame-liveness compaction. A local can be dead in its frame while a value loaded from it stays live on the operand stack across an allocation. A reduced decoder tuple failed under Tiny collection before this fix and passes now. The serialized exact-root map grows from 3,337,733 to 3,340,841 bytes; both versions report 33,724 safepoints and 101,526 callsites. Collection remains enabled.

[Subtype checks](../../../src/core/runtime/gc/native/subtype_interval.go) now walk descriptor pointers. [Promotion planning](../../../src/core/runtime/gc/native/collect.go) calculates each rounded size-class key once and skips stable sorting when plans are already ordered. Three-sample mixed-size microbenchmarks improved from 303.3 to 258.2 µs for immediate promotion and from 342.1 to 293.7 µs for survivor aging, with unchanged allocation counts. A shallow subtype check improved from 14.60 to 12.56 ns. The whole-command comparison measures the combined changes; it does not assign a separate whole-command gain to each one.

The new native constructor admits typed collector-reference fields. It checks handle liveness, object bounds, and the canonical target type before publishing the parent. Final targets use exact identity; open targets use subtype intervals. Bad or stale values take the rooted helper path. A stress-collection test and a subtype test cover this route. In the pinned optimizer, 19,255 typed constructor sites became eligible, leaving 811 sites with function or external reference fields on the helper path. The artifact run kept collection enabled and produced the same output bytes.

The collector now reads a descriptor through its canonical pointer and reuses checked object bytes for typed struct reads. The isolated final reference-get median fell from 18.69 to 10.11 ns/op, with no allocations. Abstract `ref.test` on live objects now checks the handle without loading an unused descriptor; isolated `any` tests fell from 12.46 to 6.37 ns/op. Empty native-batch cancellation skips unused cleanup. The whole-command run measures these changes together.

A profile after typed constructor admission, before open getter admission, measured 21.27 seconds in generated native code, 38.41 seconds cumulative in the host loop, 22.35 seconds cumulative in GC struct helper dispatch, 9.36 seconds in remaining initialized struct construction, and 5.31 seconds in typed helper reads. These call stacks overlap. The pinned optimizer has 19,640 static open-type `struct.get` sites; 17,137 scalar, packed, or collector-reference sites are candidates for the new native path. Three later runs measured 48.481, 48.616, and 48.717 seconds, with identical output and 22 Go GC cycles each. The remaining 48.616-second median is still about 23 times Starshine's native run (2.118 seconds on the earlier comparison). Starshine also decodes the original input again for size selection and eagerly validates it even when the smaller optimized output wins; that work is inside the guest optimizer.

The post-getter diagnostic profile sampled 24.01 seconds in generated guest code and 25.85 seconds cumulative in the native-to-Go host loop. GC struct helper dispatch fell to 15.40 seconds cumulative; typed helper reads fell to 0.49 seconds. Initialized struct construction still accounted for 9.54 seconds cumulative, and nursery promotion for 6.01 seconds. These call stacks overlap, and the profiled run has measurement overhead. The remaining opaque function-reference constructors and guest validation/size work need separate treatment; skipping token checks or collection would change the safety contract.

Go cumulative allocation traffic rose from 5,625.15 to 5,637.72 MB at the median (+0.2%); malloc count rose from 2,070,521 to 2,191,613 (+5.8%). Median Go GC cycles stayed at 22. These are Go process counters, not Wago collection counts or peak memory measurements.
