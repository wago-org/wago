## Scope and executable fixtures

Two uniquely named rfwgc_stage3_measurement_bench_test.go files are the only
changes outside this directory. Go excludes them from shipped builds; scripts and
evidence are not linked into the product. Thus this harness-only commit cannot
affect production performance. It does not waive independent measurement of the
runtime implementation. Candidate performance-sensitive paths are
src/core/runtime/gc/native/{alloc.go,eden_regions.go,collect.go,collector.go,
config.go,native_alloc.go,native_view.go,verify.go}, collector private layout,
and checked guest allocation fallback in src/wago. Workloads are the native
and guest cells described below plus identical compile controls and the catalog.

Guest fixtures use real Wasm binaries assembled by wasmtest, decoded/compiled by
Wago, and executed with the constant result oracle 7. The graph constructs a
32-node self-typed linked chain, escapes through a mutable global, replaces it
on the next invocation, and requires 32 reachable objects after full collection.
The noGC and scalar modules are distinct compile/runtime controls. All use the
same CoreFeaturesV3, inline=false, gc-lifetime-analyze=true configuration on both
pins. Compiler lifetime charge behavior is reported, not presumed to equal native
materialization. On/Off here means NurseryRegionShift 8/0, not compiler analysis.
The noGC module has no collecting-frame support, so region configuration is
inadmissible at this pin; its same-head comparison is explicitly Off/Off, a
negative control, not a region hit. Scalar and graph compare actual Off/On.
Eden and survivor are each 4096 bytes. Large arrays use existing LOS.

Native fixtures separately cover scalar churn, a 64-node escaping reference chain,
1/256 and 256/256 survivors, explicit minor promotion to old space, and 256 large
64 KiB array allocations per cycle. Each cycle checks reachability/Verify and
drops roots/full-collects to zero. Those checks and cleanup are included in the
native cycle benchmark cost on both sides; this is not a pure allocator latency
measurement. Guest runtime cost includes Invoke and scalar result checking;
compile cost includes Compile and Close, with bytes/config prepared outside timing.

The harness records actual allocation charges, minor/full collections, copied
and promoted bytes; native test logs include complete Stats. The graph manifest
records generated byte hashes, not lexical constructor guesses. These are narrow
synthetic fixtures, not the full host/shared-domain/EH/cyclic-array corpus.
Native correctness logs also capture live-checkpoint region used extents, layout
bytes by space (1=nursery, 2=old, 3=large), Eden/survivor bumps, backing lengths/
capacities and handle counts. Native benchmark diagnostics after timing record
post-cleanup backing/counters. These are point observations, not peak RSS or
fragmentation histories; do not infer peaks from them.
