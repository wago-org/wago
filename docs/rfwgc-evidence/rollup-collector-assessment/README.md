## PR1019: adopt bounded mark reset and evacuated-card cleanup

Actual scope: `barrier.go`, `collector.go`, `mark.go`, `survivor.go`, `fixed_collection_cost_test.go`, and two documentation files. At current mature target, `clearMarks` still clears the complete bool slice; card cleanup still separately clears remembered metadata and card lists. Mature descriptors do not replace either algorithm.

Adopt:

1. `Collector.markHighWater` and Close reset; bound full clear by both drained high-water and queued handles. Preserve queued old-handle bounds in `clearNurseryMarks` before discarding the stack. Keep all three drain updates (full, nursery, captured nursery).
2. `clearRememberedMetadata` clears each remembered owner's `cardSlot`, then calls shared `clearCardLists`. Reuse scalar slice tails without zeroing unreachable capacity; reset slot bitmaps, free-card head, fallback/cache state and native card view. Keep `clearCardMetadata`'s owner traversal for callers not covered by the complete-evacuation invariant.
3. `finishMinorCardMetadata` removes its now-redundant second card-clear call only on complete evacuation. Surviving-young and full-collection paths must retain remembered/card evidence as before.

Mature integration: preserve `CollectFull` ordering: cancel native reservations, trace/sweep, rebuild Eden, prune remembered, finish full card metadata, then attempt `reclaimEmptyMature`. The latter may fail after completed Eden/card cleanup and retain pending debt/candidates for retry. Do not move fast cleanup before successful promotion admission, or clear persistent/remembered inputs on an admission refusal. Existing stage5 consumed-card retry and high LOS-card tests are explicit controls. Changes to Collector footprint tests must reflect the combined fields, without inventing a native-view ABI change.

**Source-established combination hazard (not a bug in either isolated PR):** 1019's high-water is maintained by serial drains and undrained `markStack`. 1020's `drainParallel` moves seeds to worker-local stacks and empties `markStack` before dispatch (`parallel.go:99–108`); helper `mark` sets `c.mark[h]` directly, and parallel return bypasses serial drain updates. A naive combination can leave marked handles outside the reset bound, retaining dead objects or suppressing later rescans. Never update the single high-water unsynchronized from helpers. Either record per-worker maxima including seeds and claimed descendants, then merge after join (and account for failed-phase marks), or conservatively widen the clear bound before dispatch. The latter is safe but forfeits bounded clearing for that phase. Preserve the serial panic/minor/full repair whichever approach is used.

Required new deterministic regression: large graph forces helpers, high handles become unreachable, full→full and full→minor→full reclaim them; then reuse handles and introduce a newly reachable child so stale marks cannot hide missing traversal. Assert exact reachability against an independent oracle, not only absence of panic. Include forced serial fallback and interrupted root enumeration between phases.

## PR1030: adopt active array reservation preservation

Actual scope is only `native_alloc.go` plus `native_batch_cancel_overlap_test.go`. Current mature target retains the old `discardNativeStructHandles` fallback: `compactNurseryHandles` reconstructs the young ledger/bump from published handles. An independently reserved array has a still-free handle and reserved bytes invisible to that reconstruction. The source test deliberately reserves a struct/chunk batch, then an independent array, cancels the first batch, and allocates again while the array remains pending. That scenario remains relevant in default mode.

Adopt the latest fallback:

- Keep the exact-tail fast trim.
- When `nativeLargeArrayAlloc.Cursor < Count`, retain the reserved handle as well as published young handles; do not recompute bump solely from published extents.
- Otherwise use normal compaction and preserve only genuine pending dead-charge high-water. Keep the promoted-object/no-array regression so cancellation can reclaim an empty nursery.
- Optionally outline this **latest** body using the tune branch's helper shape; do not restore `Count != 0` as the pending predicate or the old unconditional no-rewind behavior.

Region correspondence: `98939b4dd` introduced `cancelNativeRegionChunk` with exact owner/end checks and bounded tail release. Keep that branch, epoch advance, cursor/count invalidation and successful object accounting. It does not fix default mode's independent reservation. Region mode refuses native large-array reservations, so it cannot execute the identical pending-native-large fixture; verify that refusal explicitly and test small native chunks followed by checked LOS allocations instead. This is a policy-specific test adaptation, not whole-PR supersession.

Mature overlap is behavioral, not a direct alloc.go patch conflict: checked LOS allocation now opens/restores mature transactions on allocation failure, collection/retry, and publication failure. Keep all those boundaries, plus prior cancellation before any backing relocation. No canceled native batch may free a live/pending identity twice or unwind an admitted mature extent. A rejected LOS attempt must leave zero descriptor reservations; a retry must retain roots, exact live bytes, other pending native ownership, and bounded bumps. Do not broaden cancellation to destroy an independent still-valid array reservation merely to make the test pass.

## PR1020: useful parallel foundation, insufficient full Snap parity

Adopt its Go-specific architecture: stable handle epoch claims with atomic unique ownership; worker-local trace stacks and bounded shared queue; reference-array chunks; coordinator-only root/ownership callbacks, allocator/card changes and handle publication; parallel sweep *discovery* with serialized release; admitted disjoint payload copying before serialized handle publication; lazy pool creation and Close drain. Keep Workers configuration/CLI validation, Tiny/TinyGo serial exclusion, custom object-edge-source serial fallback, fixture and graph/rollback/epoch/queue tests. Wago's stable handles and Go backing make these pieces more suitable than literal Slipstream pointer-forwarding or futex code.

The current mature transaction makes a useful insertion boundary, but needs deliberate adaptation:

1. Serial planner reserves every actual physical destination, prepares descriptor capacity and passes all injected precommit points. Workers must not allocate backing, grow descriptor storage, mutate free trees, open nested admissions, publish handles or change card/native views.
2. Existing `commitMatureAdmission` converts reserved bytes to live occupancy immediately before serial copy/publication. If copy can now fail recoverably, defer that conversion until all copy workers have joined successfully. Keep source handles and bytes intact until the phase cannot fail. PR1020's worker-side `poisonYoungSource` is only safe under its original no-failure-after-admission assumption; move poisoning to successful coordinator commit or provide a proven rollback strategy when adding contained helper failure.
3. After successful join, coordinator converts descriptors and publishes stable handles/major index/young census once. Failed prepublication work restores allocator reservations/backing, leaves source payloads and root/card inputs retryable, and refreshes native views only at the existing boundary. A genuinely destructive contained failure must poison admission and prevent reuse until a defined teardown; it must never report successful rollback.
4. Parallel sweep helpers only discover handles. Coordinator release must keep `releaseMature` accounting and pending-free ownership; run empty-descriptor retirement exactly once after join and existing card/Eden cleanup. An empty page is not a second allocation span to free.
5. Merge 1019 mark bounds before enabling the parallel return paths. Preserve current sorted physical-size promotion plans and region-mode exact-span admission; the tune dense-list shortcut is valid only after all native pending reservations are reconciled and every young live handle is counted exactly once.
