Parameter ownership and entry preservation
ARM64 compactFrameHeader implies register ABI for admitted functions: admission
excludes EH and GC frame plans that could force the noncompact header. Numeric
register-ABI signatures fit the X0..X7 bank. All transferred registers belong to
the allocatable bank, are unique and unreserved under the current target pools.
Target pins remain disabled for the pilot; shared owners become authoritative.
Incoming nodes have home zero, so eviction requires a real spill instead of
borrowing an uninitialized parameter home. Wrapper ABI and AMD64 continue to
establish parameter memory homes.
ARM64 entry frame-size, fence and interrupt work uses X16/X17, preserving argument
registers. Supported bodies do not invoke FP/vector, global or loop constant
preloads. Module-global reservations are separate from the argument bank.

Final return and tagged payload
returnValue releases only local-binding references. Stack roots and deferred
edges retain any old local versions required to compute the final result.
No local is observable afterward; admission permits explicit return only at
function depth immediately before final end. Memory homes remain physically
valid during final materialization even though their local bindings are cleared.
Targets do not write these homes during that terminal phase. The source node
kind guards interpretation of constant: register provenance is never treated
as an immediate. Raw incoming self-materialization retains its marker; moves
to another register, loads, computed results and recycled nodes clear it.
Normalization changes only the final physical i32 carrier, with no pending
effect/trap to reorder. Fixed-register operand ownership remains unchanged.

Control homes and frame proof
Conditional agreements store unhomed incoming parameters before restore creates
borrowed nodes. Existing captures of old roots precede home overwrites; clean
home invalidation and result/local alias proof remain intact. ARM64 rejects
frame operands, so every emitted shared frame access passes through Load/Store
and sets scalarFrameUsed. Return spill stores do so as well. Frame elision also
requires compact register entry, single register result, no calls, no spill
slots and the applicable option. Wrapper parameter/header stores cannot elide.
Declared zero homes can remain deferred because their first borrowing restore
follows a physical agreement; EH/GC are excluded at admission. Entry cold trap
unwind restores the saved runtime SP/continuation independently of frame size.
Source-recording configurations remain on fallback. No new metadata ownership
or mid-function state handoff is introduced.

Test assessment and limits
New structural tests check in-register accumulator ownership, terminal owner
release, and real spills/reloads for unhomed incoming values. Public execution
coverage uses all eight mixed-width GP arguments, an older read across overwrite,
both if edges, declared zero and tail return, plus dirty i32 get/tee returns in
both ABI modes. ARM64 diagnostic comparison requires ordinary scalar leaf code
to match the established path byte-for-byte, with no frame/spills/reloads.
Parent-run correctness and performance logs supply execution evidence; this
reviewer ran none. A focused option-disabled frame test would add a regression
guard for the corrected policy branch, but no unresolved source blocker remains.
Native ARM64 qualification remains a separate evidence requirement.

Appendix: batched terminal local-root release, 2026-10-04
Base HEAD 502d8b1a40cae2d995e304df1c4acaafec43f7ee; reviewed uncommitted
shared/scalar.go and run_me.sh changes. Source inspection only; no builds,
tests, timings or profiles. No concrete correctness defect found.

Each consecutive group represents count distinct owning references to the
same live ID. count is positive and <=256; the checked assertion requires
refs >= count. Subtracting count-1 then releasing once removes exactly those
roots and leaves the ordinary final release responsible for register, spill
slot, free-list and deferred-child cleanup. Later groups of that ID still
contribute their references, so the node cannot die prematurely. Recursive
release cannot destroy a node retained by a future local or result/deferred
root. No node add/reuse occurs during this terminal grouping loop. Clearing
the locals after all groups therefore cannot expose stale recycled IDs.
Materialization still follows root release with the result root retained;
valid physical homes, spill slots, raw-i32 payload markers and effect ordering
are unchanged. The grouping scan and final clear remain bounded O(nLocals).
Alternating identities add branch work without batching benefit; measured
timing, rather than the source change, must establish this tradeoff's value.

Existing 256-local tests cover long same-zero runs and alternating repeated
width IDs. A direct A,A,B,B,A,A case with A retained as the result would add
a guard for repeated long groups; this is a nonblocking coverage suggestion.
The run_me full-test split executes only the exactly anchored named installer
test with the isolated tree's go.work and skips only that exact test in the
GOWORK=off full run. Explicit per-command overrides take precedence over
workspace auto-discovery. Both normal and checked configurations keep the
same test coverage; no production behavior changes in the script.
