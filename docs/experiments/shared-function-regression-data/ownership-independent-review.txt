Join identity and ownership
The then edge records a local index only when its binding and the single
result root have the same live stable identity. The else edge independently
checks that same index against its result before any relation is retained.
Matching numerical values or registers do not substitute for identity.
canonicalize retains its existing capture-before-store ordering, writes local
homes and the operand prefix, moves the single result to its agreed register,
then restores logical state. restoreResultLocal releases the freshly restored
borrowed local, retains the live result, binds that local to the result, and
marks the already-valid home. No target instruction is emitted by this step.
The result root remains independently referenced throughout.

Home validity, nesting, and effects
Each incoming edge established the selected local home before the physical
join. A previously clean home is skipped only when its retained invariant
already proves validity. Later overwriting its original binding clears home
before realization/spilling; other retained result or local aliases survive.
Rebinding another local does not invalidate an unchanged source home. Nested
joins apply the same independent edge proof; resultless/no-else controls never
attempt result alias restoration. Multiple alias possibilities may miss an
optimization because only one index is remembered, but cannot invent an
identity relation. Control frame layout uses existing padding on these targets.
Admission, trapping/effect boundaries, return preparation, and target ABI
ownership remain unchanged. The extra local scan is bounded by 256 entries
and occurs only at a single-result then exit.

Run-length admission
Positive-count runs enforce integer width, total count <=256, and a bounded
count before integer conversion. Parameter/result checks and legacy bytecode
budget remain in the shared scanner. Initial zero-width accounting matches
expanded types; body emission still streams the original validated bytes.
Both adapters call the same scanner inside the existing admission timer.
No payload-retaining instruction array or second semantic state is introduced.

Test assessment and limits
Parity tests cover zero/positive/over-limit counts, integer/noninteger runs,
mixed widths, and repeated run ordering. Execution fixtures cover both same
local edges, different locals, overwrite before/after the join, and all three
nested paths, with both widths and ABI modes. They establish eligibility
directly; actual migration remains a separate diagnostics assertion when a
global switch may disable the shared path. Checked and native/emulated success
must be attributed to the parent-run logs, not this source review. Native
ARM64 and OS mapping identity qualification remain separate existing limits.
