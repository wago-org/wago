# Native AMD64 thread and compact-import baseline

Hub's Ryzen7 7800X3D now runs the frozen334732e1 Wago SDK with Go1.27.1 against pinned f303ed27 SIMD w2c2 compiled with Ubuntu Clang18.1.3. Both source orders use CPU7, explicit Wago bounds, and the same artifact/contract hashes as the ARM64 campaign. The Clang peer retains the existing -O3,-march=native,-fno-strict-aliasing,pthreads and disabled runtime-check configuration. These are same-host native measurements; do not substitute ARM64 timings.

All16 captures and64 phases pass source/artifact/contract checks,15 samples per successful phase, and memory/code resource audits. Ordinary compact imports take30.350/30.494 milliseconds versus1.122/1.124 milliseconds,27.05/27.13 times the peer. Ordinary thread callbacks take6.336/6.355 milliseconds versus0.624/0.624 milliseconds,10.16/10.18 times. Opaque owned Go callbacks take6.409/6.457 milliseconds versus0.624/0.625 milliseconds,10.27/10.33 times. The minimal dependent callback loop is6.446/6.442 nanoseconds versus2.151/2.139 nanoseconds,3.00/3.01 times. No native parity is achieved.

In this source, AMD64 RegisterNativeScalarLeaf returnsfalse. ARM64's separate implementation verifies and clones bounded ordinary Go scalar leaves. The missing AMD64 path is the next investigation; the measurement alone does not quantify the gain a port will achieve. Owned opaque callbacks must retain actual Go execution and ownership semantics.

This is a private four-contract baseline, not a complete native feature/source snapshot. It is not ingested into the local website or production. Source inputs and executable hashes are recorded privately; the runner persists in tmux and a local watcher requests saved-boundary pauses. Initial native capture preparation failed because the independent analyzer was absent; that attempt is preserved separately and contributes no timings. The analyzer is now built from the matching wasmparser0.251.0 source and pinned by executable hash. Host desktop applications remained running.
