Initial state: created by makeFS during provider Start; owned by Plugin; Plugin.fs is the availability marker. The first resolved instance also aliases it through guard.states exactly once because guard.claimed never resets during use. After that instance closes, Plugin.fs still retains the terminal state, but later instances use distinct makeFS results.
Later state: created by stateFor for a fresh validated identity; owned through guard.states; a callback temporarily borrows it under state.mu. closeInstance removes the identity under guard.mu, then waits on state.mu before terminal cleanup. Revoked callers cannot recreate the removed identity through the public API.
Descriptors: file and dirIter fields are owned; standard reader/writer interfaces are borrowed. closeFS closes only owned files. makeFS failure owns unpublished state exclusively. Stop closes all remaining states after preventing new state resolution. No production path reuses a terminal descriptor map.
Patch 3 only drops state.fds after the existing close loop. It does not clear Plugin.fs, change guard.claimed, change capability checks, or change locks.
