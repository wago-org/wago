## Findings and existing fixes

The bot found a P1 in `gc_rooted_scalar.go`: widening the type cap allowed a
14-byte malformed module to request about 512 MiB of parser scratch before
its missing declarations were rejected. CI also had four red checks. The
reported CI cause was an unconditional amd64 backend import from a Linux
test file, breaking native arm64 and riscv64 builds.

- `f9ff504dd48338f5cbd6f3a6dc14b25602639b2f`
  (`fix(rv64): bound rooted wire scratch by payload`) rejects a wire group
  count larger than the remaining payload before sizing parser scratch.
  Its regression test,
  `TestRV64RootedScalarTypeWireRejectsCountBeyondPayloadWithoutAllocation`,
  rejects the malformed 14-byte fixture and asserts zero allocations using
  `testing.AllocsPerRun(100, ...)`.
- `430d57665389b9ba4712431e564933dda40fd424`
  (`test(rv64): isolate amd64 type cap control`) moves the amd64 control
  import and implementation into a `linux && amd64 && !tinygo` test file.
  A `linux && !amd64 && !tinygo` helper permits the RV64 suite to compile
  on other Linux architectures without importing the amd64 backend.
