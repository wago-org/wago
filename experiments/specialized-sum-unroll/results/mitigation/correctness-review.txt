Paired remainder
- sum_unroll_experimental.go:177-201: the zero test skips all remainder loads. An odd remaining count branches to the second half and consumes one element. All subsequent visits consume two elements. Each load has native offset zero, each address increment uses 32-bit arithmetic, and each counter decrement uses 32-bit arithmetic. Thus each next load uses the memory32 wrapped address, including a wrapping range selected by the earlier dispatch.
- The loop branch immediately follows the second counter subtraction. It does not use flags from the first subtraction or address increment. Odd and even counts therefore terminate with counter zero and the expected wrapped address.
- sum_unroll_experimental.go:193-208: the second half adds into p1; the first half adds into the original accumulator. p1 includes any main-group partial sum and is combined exactly once. Addition modulo 2^64 permits this regrouping. The original range proof, scalar peel, main group, wrap dispatch, and live-local treatment are unchanged.
- sum_unroll_experimental.go:78-101: pair emission is restricted to factor 16/chains 4 without a hybrid or threshold arm. Configuration, conservative byte budget, and availability of all temporary registers are checked before emission or pin mutation. Storage remains the fixed [8]Reg array. Cleanup is shared with the earlier emitter at :209-213. No new temporary register or heap object is introduced by the paired remainder.
- sum_unroll_pair_test.go now directly verifies adequate-budget rejection with all allocatable registers reserved, including unchanged bytes and allocator ownership. This closes the earlier register-pressure coverage request. Budget fallback still executes the original path against the independent oracle.

Capacity hint
- compile.go:1917-1928: the hint is collected inside the existing totalBody loop. It changes only the capacity estimate passed to the existing buffers; it does not clone a module, scan instructions again, alter recognition, or alter Wasm instructions.
- sum_unroll_experimental.go:228-248: activation requires the private reserve flag, factor 16, four chains, no hybrid or threshold, deferred mapping, one worker, and effective noncompact compilation (including WAGO_COMPACT). The caller also disables the hint when a memory-pressure callback uses the implicit threshold. Per-function headroom is 128 bytes, limited to 1024 bytes per module, and excludes empty/large bodies, non-i64-first-result functions, and missing loop/memory or call/tail/SIMD/bulk-memory hints. The used-limit checks and caller addition-overflow check bound arithmetic. LocalFuncType returns the existing module type; it does not allocate a new resolved type wrapper.
- The broad existing hints are a sizing heuristic, not proof that the sum recognizer will admit a loop. False positives can increase allocated bytes within the stated bound. They cannot enable emission or change runtime instructions.
- sum_unroll_default.go contains constant false/zero stubs. Normal builds remain on the original emitter. The new condition can be eliminated by normal Go inlining. A compiler optimization log or a disabled-experiment compile benchmark should verify the intended absence of measurable ordinary-compiler cost; I did not build a binary to check this.
- sum_unroll_capacity_test.go:52 onward now compares reserved and nonreserved native bytes, Entry, InternalEntry, DirectPrepared, and PreparedIsolatedTables on the two-function deferred/one-worker path. It then executes the reserved compilation at an unaligned address against the oracle for zero, odd/even, group boundaries, and 512 elements. This directly covers the arena/join capacity intervention.
- The public allocation test correctly switches factor to zero for the baseline while leaving mitigation flags unchanged. The factor gate disables the hint in that state. The tests-first failure records candidate 110 versus baseline 108 allocation objects; capacity-after.txt records the test passing after implementation. The passing log does not print the resulting absolute count, so only equality is independently established from that log.
