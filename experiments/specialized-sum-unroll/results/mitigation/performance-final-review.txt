P: failed useful mitigation
Normal-to-P n16 losses repeat in both alignments: aligned +2.06%/+2.35%, unaligned +2.11%/+1.75%, all significant. Initial aligned n63 +1.40% is retained and unrepeated. Initial aligned n64 +1.91% and repeat unaligned n64 +.90% are also retained. Cache gains against normal Wago mostly include D's unchanged main-group benefit and do not isolate paired-tail value.
Direct D/P first aligned n16 -1.32%(p=.014) becomes -.42%(p=.337);first aligned n512 -1.36%(p=.016) becomes +2.42%(p=.229). Neither small initial gain repeats. Direct confirmation instead has unaligned n8 +1.64%(p=.037) and n8192 +1.21%(p=.008) losses. Other direct differences are not significant. These data support rejection under the frozen criterion: no coherent short-loop recovery and no broad, repeatable advantage over D. Twenty-two execution rows are repeated; the report marks original boundary and compile rows that are not repeated.
The one-set public P cost qualification shows execution 96.49->90.64ns, -6.06%, p<.001;public compile 22984.5->22975.5ns, -.04%, not significant;allocation bytes 23360->25153, objects 108->110. Lifecycle 24945/117->26737/119. It does not establish a free or faster lifecycle, or a repeated public P gain. Its allocation-count cost remains D's. PR was not timed because P failed the declared performance rule. Correctness/byte-identity checks of PR are not performance evidence for PR.

DR: allocation mitigation with costs
Normal-to-DR synthetic memory.sum execution improves 9.57% then 10.12%, p<.001 in both sets. Public memory compile changes +.0022%(not significant) then +1.33%(p=.027). The significant repeat loss is retained; no compile-time reduction was established. Lifecycle +.30%/+.47% is not significant; no faster one-call workload or equivalence is established.
Public memory compile 23361->23617 B, 108->108objects, and lifecycle24945->25201B, 117->117objects, repeat on both primary comparisons. DR removes D's two growth objects but adds 256 preallocated bytes versus normal 4/4, about 1.10%. This is an object-count mitigation, not unchanged public memory use.
The direct D/DR first public result 25153->23617 B removes 1536 B and two objects. Direct repeat 25153->23616 B removes 1537 B and two objects;the report now keeps this one-byte accounting variation. Lifecycle 26737/119->25201/117 removes 1536 B/two objects. Every direct timing difference is not significant. Repeat raw compile +5.01%, public +1.53%, lifecycle +3.31% remain visible. Native instruction equality does not imply equal total observed timing.
Median-only arithmetic recovery values 1 call and 32 calls for the two normal DR sets, and 0 calls for P's negative compile median, are mathematically correct. The report explicitly states that these are not statistically established break-even points. The tiny or negative median compile differences do not prove instantaneous profitability. No useful application call counts were found.

Controls and reserve false positives
YYjson execution has a repeated zero-admission loss +1.14%(p=.005)/+1.46%(p=.014). Its native bytes and zero headroom are unchanged. This rules out attribution to emitted sum instructions, but does not remove the measured loss. Host layout/initialization or another timing effect was not isolated. The report retains the loss and does not claim all adjacent workloads are unaffected. Positive one-set control changes remain unattributed.
The disabled normal control has 25 rows, no changed allocation count, and no significant time difference(minimum p=.102). Four public byte medians have small differences of at most 1 B, also retained. This supports no detected ordinary-compiler regression in this set;it does not prove equivalence or bit-identical whole compiler code.
The headroom scan has 121 files, 120 decoded modules and one explicit disabled-EH MicroPython exclusion. Fourteen modules request logical headroom;thirteen are predictor false positives relative to exact sum recognition. The per-module bound is 1024 logical B, not total heap-byte growth. Worker and join can both reserve capacity, and Go size classes can increase physical cost. Seqtk local function 5 requests 128 logical B with zero exact native sum admission. Its large serial heap path reduces the request by 25%;the approximate 96 B increment may remain in one size class. Its raw/public object counts do not increase in the measurements, but this is not a worst-case false-positive allocation test. Actual public byte medians have small accounting changes and remain in CSV. No general zero-cost reserve claim is made.

Reproduction and recommendation
mitigation.sh builds timing and diagnostic binaries and runs validation before serial measurements. It reproduces the fixed initial/confirmation matrices, and deliberately does not time PR. The optional earlier normal binary is necessary for the historical disabled control;when absent, the script explicitly omits that control. Current normal Wago remains the primary baseline. The old hash remains saved. This limitation is stated in the report. Scripts do not perform another threshold/layout search.
DR is the best measured allocation mitigation in this bounded study: it restores object counts and preserves D's guest code at a 256 B memory cost. It does not repair D's short losses or prove application profitability. P's negative direct/repeated evidence justifies rejection as the next optimization to adopt. Retain both implementations/evidence opt-in, keep production 4/4, and investigate actual eligible workload coverage before promotion. This final recommendation is supported. No universal fastest configuration was proved.
The review does not replace correctness/test/CI validation. Checks were still running. Known earlier shared-scalar failures, unavailable Claude review, cross-build-only ARM64, one CPU/active desktop, boost enabled, absent hardware counters/layout isolation and absent eligible application gains remain limits. The final report must record the actual completed check status.
