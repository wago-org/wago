# Not retained: exact unsigned widening dot loop

Apple M4 Max, arm64; isolated source commit `37174169` at `/tmp/wago-widening-dot-37174169`. Main production compiler source was never changed. One complete prototype was measured and profiled; the startup mitigation below was only proposed, never implemented or timed. No production hook, option or default is imported from this archive.

The [plan](widening-dot-plan.md) and [source-only patch](candidate.patch) admit a bounded read-only call-free kernel, including inside a calling function: two full unsigned 32×32 products accumulate modulo 2^64, forward/backward i32 streams advance8 bytes, and a−2 modular counter reaches an invariant equality limit. Nonzero/even dynamic distance and widened whole-memory ranges guard vector entry. Reversed lanes use REV64+EXT, UMULL/UMULL2 and 64-bit vector additions. Guard failure preserves the original scalar body; an odd vector residual executes one original two-product iteration. Final guest pointers/counter are restored modulo 2^32. Shared memory, interruptible loops, EH/custom lowering, regional pins and incompatible caller-pin state decline. No 28-bit limb or corpus identity assumption is used.

Both source files are disabled evidence: [helper](widening_dot.go.disabled), [fixtures](widening_dot_arm64_test.go.disabled). The parser is bounded to 32 locals,128 nodes,24 stack values and 256 source bytes; a fixed four-GP/four-V register preflight emits no spill or failed-allocation effects. Unpinned integer assignments store immediately to canonical native frame slots (`driver.go`1325–1334); zero initialization and existing loop-entry reconciliation establish valid slots before the new read seam. Calling-function admission requires the existing call-free entry/region mechanism. Empty logical stack after flush excludes older operand snapshots; the dedicated pending-divide fixture checks an older discarded trap before memory access. Modified pins remain dirty registers and unpinned locals remain canonical slots on fallback, residual and complete paths.

The [strict fixtures](widening-dot-strict.txt) passed under `wago_codegenstats,wago_regalloccheck,wago_guardpage` in both bounds modes, with arbitrary/full-width values,64-bit sum overflow, dirty upper carriers, overlap/unalignment, wrapped counters and final B=−8, scalar residuals, short/zero/odd-distance fallback, OOB, outer calls, pending divide trap, compact execution and native widening/shuffle assertions. Store/shared/interruptible exclusions also passed. This is focused qualification; all 148 application/core oracles and full inventories were not run.

The [8×150ms focused screen](widening-dot-screen-summary.md) did not show a gain:

| LibTomMath modular arithmetic | Median paired change | Paired IQR | Pooled median change |
|---|---:|---:|---:|
| Steady execution | +0.70% | −0.35%..+1.14% | +0.38% |
| Compilation | +0.20% | −0.62%..+0.69% | −0.04% |

The LibTomMath image grew 93588→94356 bytes. The [three control images](native-proof.txt)—register allocation, dilation and Reed Solomon—remained byte-identical; their execution drift in the [6×100ms control screen](widening-dot-control-summary.md) is not an optimization gain. Dilation compilation rose+0.65% paired (IQR+0.58..+0.77), but unconditional source/struct-layout cost against a pristine compiler was not measured. No flat source-cost claim is made.

The [3-second profile](profile-widening-dot-on/) passed the exact oracle and [embedded-native identity check](widening-dot-profile-native-proof.txt), matching the 94356-byte timed candidate. In [f28 assembly](profile-widening-dot-on-assembly.txt), the new vector region+67c4..67f4 received 0 leaf observations, while startup guards and the unchanged scalar loop did receive observations. This is consistent with short-trip/startup cost, but the sample counts do not establish path frequencies or cycle weights. A second emitted vector region is also visible near+113d4; no complete 148 image-scope claim is made.

A proposed general mitigation would test the trip count before reading pointers/seed, reuse the unused owned accumulator register as guard scratch, compare `max(A+8N,B+8)` once each against memory size and2^32 after proving the descending lower bound, and require enough iterations to amortize startup. It was not implemented or benchmarked: the user requested wrap-up, and the completed result did not justify more qualification. The prototype remains rejected for this production change.
