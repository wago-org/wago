# General residency follow-up

Retained Reed-Solomon source was decoded from its manifest artifact to `/tmp/reed-solomon-current.wat`. The function declares80i32 locals. It computes several words, assigns individual masked bits into many long-lived locals, then reads those locals in repeated select/XOR update chains. This is source structure, not proof that spills dominate time. A fresh frozen-retained profiler capture is queued as `profile-branch-vector-retained-residency-graphics-reed-solomon`; use its exact sampled code before deciding an implementation.

One possible broader optimization is shared rematerialization of cheap masked-local snapshots. It must preserve each local.get's value at read time when the original producer is overwritten, preserve assignments at every control join, materialize canonical locals before observable calls/GC/EH state, and correctly invalidate snapshots on memory effects where relevant. A source-register reference alone is insufficient: this function immediately overwrites the producer for the next word. Captured snapshots would need stable owned storage and bounded lifetime metadata. Ordinary locals currently have canonical homes, so changing only local.set is not enough; every load/condition/spill/branch path must agree on the new representation. No implementation is proposed without evidence that the benefit warrants this complexity.

Another broad direction is loop vectorization with a compile-budget model. The archived store-map prototype gave large resize/max-pooling/components gains but paid9–20% compile overhead even where execution was nearly unchanged. It was correctly rejected after multiple mitigations. Reinstating it requires a new general analysis/emission cost reduction or a defensible static profitability proof, not choosing the strong benchmark names. Trip-count and candidate-loop share of total work are potentially relevant but must be proven from guest source, never manifest args or workload identity. No restored store-map production code is authorized by these notes; current retained baseline is unchanged.

Fresh Reed profiler capture completed: stack loads appear across the select/XOR region, with no single hot instruction dominating. Constant-i64 initialization stores have explicit proofs even in signal mode, correctly preventing unaligned partial writes. Regional address pop snapshots lose the source identity, causing repeated checks for descending stores. The next experimental implementation targets this lifetime boundary directly via a temporary pinned address loan; it does not relax store trap/partial-write semantics.
