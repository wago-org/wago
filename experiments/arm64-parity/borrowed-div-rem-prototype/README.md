# Borrowed division/remainder operand draft

Unintegrated in production. Isolated diagnostics and all148signal exact oracles pass after explicit result-destination alias protection; confirmation, broader affected timing and explicit-bounds qualification are pending. Current lowering copies divisor into an owned register, allocates dividend storage and copies into it. The draft reads both through `materializeRead`, pins them during allocation, restores inherited pins and releases only owned operands. It retains the existing constant-divisor lowering, divide-zero checks, signed-overflow checks, signed remainder handling and fresh result rules. No workload-specific eligibility.

Integrate behind a separate default-off per-compilation option after the pending leaf-scoped constant mitigation finishes. Native fixtures must exercise all four operators, both widths, zero/min/-1 boundaries and traps, both bounds modes, both switch states, preservation of both operands used after the result, identical operand aliases, inherited pins and register pressure. Diagnostic admission must show actual borrowing; compare affected native images to the common-exit retained baseline before timing. The previous direct borrowed shift/logical experiments were rejected, so do not assume copy removal wins: qualify affected execution and compilation and try a justified general mitigation before rejection.
