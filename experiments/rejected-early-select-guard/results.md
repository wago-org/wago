# Next general cover: an early guard for pure select updates

Fresh retained profiler: `profile-branch-vector-retained-next-files-glob-match`. Current source decoded to `/tmp/files-glob-current.wat` from the manifest artifact. It computes a checksum XOR/multiply before two selects that can both retain the old checksum. Existing `tryPureSelectSinkGuard` operates at the final local.set, when the inner select has already materialized the expensive expression. `beginSelectGroup` only recognizes several bitmask-controlled updates and runs after select/local.tee, so it cannot guard this pure nested expression from its first local.get.

A general bounded bytecode proof can start after a pinned declared i32 local.get. Abstract interpretation accepts local.get, i32.const, wrapping integer ALU/shifts, integer comparisons/eqz, and select; declines all memory, division, calls, local writes, control and unsupported operations. Require the final select to keep this same destination on one arm, use a simple unchanged pinned local/constant comparison on the other condition, and reach local.set of the original destination. The expensive other arm may contain nested pure selects. Require a weighted pure-work threshold; no workload IDs or literal-specific rules.

Emit the final condition before the original pure sequence, with a branch around the sequence when the destination is retained. Continue compiling original bytecode, using existing end-site patching and invalidation. The early guard must not change trap/effect order because the proof allows no trapping or effectful operations. Exclude interval/call/custom/GC/EH policies initially. Recover every referenced lazy local before branching; flush older operand blocks; invalidate caches/facts at the join. Check that allocation metadata cannot publish a spill or deferred initialization only on the skipped path. The latter is a correctness requirement, not merely a timing consideration.

Bound the abstract stack and instruction budget; add a cheap opcode/shape prefilter before scanning to limit compilation cost. Test both selection directions, comparison directions and signed/unsigned boundaries, nested selects, destination/local source reuse, lazy-zero locals, older operand blocks, rejection of loads/divides/calls/writes, both bounds modes, and strict admission. Then inventory native changes and benchmark a focused affected subset, with compile cost measured alongside execution. No implementation or performance claim yet.
